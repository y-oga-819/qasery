# テスト管理ドメイン設計書（DDD）

---

## 🧱 集約設計

本システムは「テスト管理」を目的とし、テストスイート、テストケース、テストステップ、シェアドステップという4つの主要な概念を扱う。
それぞれをドメイン上の独立した集約またはエンティティとして整理する。

---

## 1. TestSuite 集約

### 概要
テストスイートは、テストケースを論理的にグルーピングする単位である。
テストスイート自体はテストケースの実体を保持せず、IDによって関連付ける。

### 主なプロパティ
| プロパティ名 | 型 | 説明 |
|---------------|----|------|
| `TestSuiteId` | ID | スイートの一意識別子 |
| `name` | string | スイート名 |
| `description` | string (optional) | 概要説明 |
| `createdAt` | DateTime | 作成日時 |
| `updatedAt` | DateTime | 更新日時 |

### 制約
- `name` はスイート内で一意である必要はない（人間識別用）。
- テストケースは必ずいずれかのスイートに属する。

### 主な振る舞い
- スイートを作成／名称変更／削除する
- 所属するテストケースの一覧を取得する（リポジトリ経由）

---

## 2. TestCase 集約

### 概要
テストケースは実際のテスト実行単位を表す。
1つのテストケースは複数のテストステップを持ち、またシェアドステップを参照する。
並び順はテストケース内部の重要な要素として保持される。

### 主なプロパティ
| プロパティ名 | 型 | 説明 |
|---------------|----|------|
| `TestCaseId` | ID | 一意識別子 |
| `TestSuiteId` | ID | 所属スイートの識別子 |
| `title` | string | ケース名 |
| `description` | string (optional) | 概要説明 |
| `steps` | `OrderedStep[]` | テストステップおよびシェアドステップの順序付きリスト |
| `createdAt` | DateTime | 作成日時 |
| `updatedAt` | DateTime | 更新日時 |

### 制約
- すべての `TestCase` は必ず1つの `TestSuite` に属する。
- `steps` の並び順はテストケース内で一意に決まる。
- `steps` 内には同一ステップ（同じID）の重複を許さない。

### 主な振る舞い
- ステップを追加／削除する
- ステップの並び順を変更する
- シェアドステップ参照を追加／削除する
- テストケースを別のスイートに移動する
  - このとき、移動先スイートの存在はアプリケーションサービスで検証される。

---

## 3. SharedStep 集約

### 概要
シェアドステップは複数のテストケースから参照される共有手順。
概念としては、「複数のTestCaseで使い回すことが可能な、階層1の子要素（内部ステップ）を持つTestStep」である。
内容を更新すると、すべての参照元のテストケースに反映される。
他のケースから独立して管理されるため、独自の集約境界を持つ。

### 主なプロパティ
| プロパティ名 | 型 | 説明 |
|---------------|----|------|
| `SharedStepId` | ID | 一意識別子（Qase APIではハッシュ文字列） |
| `projectCode` | string | プロジェクトコード |
| `title` | string | 共有ステップ名 |
| `steps` | `SharedStepStep[]` | 内部ステップのリスト（階層1の子要素） |
| `casesCount` | int | この共有ステップを使用しているテストケース数 |
| `createdAt` | DateTime | 作成日時 |
| `updatedAt` | DateTime | 更新日時 |

### SharedStepStep（内部ステップ）のプロパティ
| プロパティ名 | 型 | 説明 |
|---------------|----|------|
| `id` | int | ステップID（ローカルDB用） |
| `hash` | string | ステップハッシュ（Qase API） |
| `action` | string | アクション（実行内容） |
| `expectedResult` | string (optional) | 期待される結果 |
| `data` | string (optional) | データ（入力データなど） |
| `parentStepId` | int (optional) | 親ステップID（ネスト構造） |
| `position` | int | 表示順序 |

### 制約
- `SharedStep` は複数のテストケースから参照可能。
- 変更は参照元すべてに即座に影響する。
- 削除する場合は、参照中のテストケースが存在しないことを確認する必要がある。

### 主な振る舞い
- 共有ステップを新規作成／更新／削除する
- 内部ステップ（SharedStepStep）を追加／削除する
- 内部ステップの順序を管理する
- 更新時にはすべての参照元に影響を与えるため、承認フローや通知ポリシーを考慮する
- 削除時には、参照中のテストケースが存在しないことを検証する（cases_count > 0の場合は削除不可）

---

## 4. OrderedStep（値オブジェクト）

### 概要
テストケースが保持するステップ（固有ステップまたは共有ステップ）の順序情報を表す。
並び順を表現し、両者を一貫したリストとして扱うためのVO。

### 主なプロパティ
| プロパティ名 | 型 | 説明 |
|---------------|----|------|
| `stepType` | enum(`OWN`, `SHARED`) | ステップの種別 |
| `stepId` | `StepId` or `SharedStepId` | ステップの識別子 |
| `position` | int | 並び順 |

### 制約
- 同一 `position` の重複は禁止。
- 同一ステップIDの重複禁止。

---

## 5. 値オブジェクト（VO）

| 値オブジェクト名 | 用途 |
|------------------|------|
| `TestSuiteId` | スイートの識別子 |
| `TestCaseId` | ケースの識別子 |
| `StepId` | 固有ステップの識別子 |
| `SharedStepId` | シェアドステップの識別子 |
| `ExpectedResult` | 期待結果の値オブジェクト |
| `OrderedStep` | ステップと順序の組を表すVO |

---

## 6. 集約間の関係性

| 関係 | 種別 | 整合性の担保方法 |
|------|------|----------------|
| TestSuite → TestCase | 1対多 | `TestCase` が `TestSuiteId` を保持し、アプリケーションサービスで存在検証 |
| TestCase → SharedTestStep | 多対多（参照） | `TestCase` が `SharedStepId` を参照し、リポジトリ経由で実体を取得 |
| TestCase → TestStep | 1対多（集約内エンティティ） | `TestCase` 内で完全に管理、一貫性境界内で完結 |

---

## 7. 整合性境界

| 集約 | 一貫性の範囲 | 外部整合性の扱い |
|------|----------------|------------------|
| `TestSuite` | スイート自身 | 所属ケースの整合性はアプリケーション層で保証 |
| `TestCase` | 自身のステップリスト（順序・重複制約） | 参照する共有ステップの存在はアプリケーション層で保証 |
| `SharedTestStep` | 自身のみ | 参照元ケースとの整合性は遅延整合性で扱う |

---

## 8. 代表的なユースケース

| ユースケース | 実行主体 | 処理概要 |
|---------------|----------|-----------|
| テストスイート作成 | テスト管理者 | 新しいスイートを作成し永続化 |
| テストケース追加 | テスト管理者 | 対象スイートを検証後、`TestCase` 集約を生成 |
| ステップ追加 | テスト設計者 | `TestCase` に `OrderedStep` を追加、順序再計算 |
| シェアドステップ参照追加 | テスト設計者 | 共有ステップの存在を確認し、`OrderedStep` に追加 |
| シェアドステップ更新 | テスト管理者 | 共有ステップ内容を更新、全参照ケースに反映 |
| テストケース移動 | テスト管理者 | 移動先スイートの存在検証後、`TestCase.suiteId` を更新 |

---

## 9. モデリング方針まとめ

- 一貫性の単位は **テストケース単位**。
- **共有ステップは独立した集約** として、他ケースから参照可能。
- **順序情報は値オブジェクトで表現**し、ケース内の論理的な並びを保持。
- 集約間の依存関係はすべて **ID参照 + アプリケーション層での整合性確認** によって疎結合化。
- 集約間の整合性は「遅延整合性」を原則とし、ドメインイベントで同期する設計も可能。
